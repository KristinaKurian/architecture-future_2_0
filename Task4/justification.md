# Task4 — обоснование инфраструктуры с ограниченными квотами

## Связь с Task1–3

Проект иллюстрирует IaC для компонентов **общей платформы данных**: учебная VM, сетевой контур, подключённое хранилище и управление доступом. Он не меняет состав четырёх бизнес-доменов. Приложения и анализ медицинских данных здесь не развёртываются.

## Почему такие параметры

| Ресурс | Параметры | Обоснование |
|---|---|---|
| ВМ portal | standard-v3, 2 vCPU, 4 GB RAM | Укладывается в типовую начальную зональную квоту 2 vCPU; демонстрация VM и SSH без промышленной нагрузки |
| Boot HDD | 20 GB, network-hdd | Ubuntu и системные файлы; вся доступная квота HDD в зоне |
| Data SSD | 10 GB, network-ssd | Демонстрация отдельного подключаемого диска; вся доступная квота SSD в зоне; не полноценное аналитическое хранилище |
| VPC | Подсети `10.40.10.0/24` и `10.40.20.0/24` | Разграничение публичного и будущего приватного размещения; заранее описаны зависимости |
| Публичный NAT IP | `nat=true` на VM portal | SSH-доступ с одного административного IPv4; ресурс получает публичный IP |
| NAT Gateway + route table | `0.0.0.0/0` из приватной подсети в NAT | Планируемый исходящий доступ будущих приватных VM без публичного адреса; в текущем стенде не используется |
| Security Group | SSH 22 только с `admin_cidr`; HTTPS 443 | Сокращение доступа к администрированию; порт 443 не означает, что TLS/сервис уже настроены |

## Почему сокращённая конфигурация

Фактические квоты пользователя для зоны `ru-central1-a`: **20 GB HDD** и **10 GB SSD**, текущее использование 0. Исходная конфигурация требовала 60 GB HDD + 50 GB SSD, а также 4 vCPU. Сокращённая версия создаёт одну VM и два диска, чтобы **не запрашивать увеличение квот**. Проверка размеров образа ОС, фактических CPU-квот, количества доступных ресурсов и тарификации остаётся необходимой.

## IaC и воспроизводимость

Terraform декларативно описывает требуемое состояние инфраструктуры; зависимости определяются ссылками на ID ресурсов. `plan` показывает изменения до применения, `apply` создаёт их и записывает Terraform state. Переменные позволяют повторить конфигурацию в другом каталоге и заменить IP/сеть/размеры без ручного создания ресурсов. В промышленном контуре state следует хранить удалённо с контролем доступа, блокировкой и резервированием, а токены — передавать безопасным способом.

## Что остаётся за пределами Terraform

IAM-права и облако, настройка SSH-доступа администратора, установка портала и TLS/DNS, форматирование/монтирование SSD, проверки качества, мониторинг приложений и резервное копирование. Это не означает, что эти шаги невозможно автоматизировать — они просто не включены в учебный Terraform-стенд.

## Оговорки

Это стенд для демонстрации VM/Disk/Network/NAT и Terraform, а не production-архитектура. Приватный аналитический сервер отсутствует, защитное разделение остаётся целевым требованием. Для масштабирования добавляют VM и диски после оценки квот, нагрузки, размещения и стоимости. Технологии Task1–3 не считаются развернутыми после успешного `apply`.
